# 求职进度六阶段

入口 `/pipeline` 只展示六个阶段入口，不显示岗位管理的统计卡、提醒横条和搜索工具栏。六个新页面：

| 地址 | 阶段 | 工作区 |
| --- | --- | --- |
| `/pipeline/apply` | 待投递 | 岗位分析建议、岗位专属简历文字草稿 |
| `/pipeline/prepare` | 准备中 | 原准备清单，逐条勾选并保存 |
| `/pipeline/assessment` | 笔试 | 考察内容、表现与复习方向 |
| `/pipeline/interview` | 面试 | 复用真实面试复盘，自动关联当前岗位 |
| `/pipeline/offer` | Offer | 具体地点、薪资福利、工作时间、每周到岗天数、到岗日期 |
| `/pipeline/closed` | 未通过 | 原因、复盘与下一步 |

## 保存与兼容

- 不新增数据库表，不修改已有 API。准备清单沿用 `prepChecklist`；真实面试沿用原面试复盘 API 和数据表。
- 简历、笔试、Offer 和未通过补充信息保存在岗位 `processRecords` 中，以 `pipeline-阶段名` 唯一 ID 区分，notes 使用 JSON 保存。沿用现有安全校验和 JSON 备份；没有日程时间，不产生虚假的日程提醒。
- 单条阶段记录受原有 4000 字符上限约束，保存前检查；到达原有 50 条流程记录上限时阻止新增，避免静默丢弃。
- 旧“已投递”岗位显示在准备中，并标记原状态，不迁移或删除已有数据。新的阶段菜单没有“已投递”。岗位管理原有筛选和状态兼容不变。
- 岗位专属简历不会覆盖共享简历版本，也不会自动修改匹配度；这次不新增生成式 AI 或自动改写简历服务。
- 原来未关联岗位的真实面试复盘仍可在面试题库“我的复盘”中查看和编辑，可手动关联岗位后在新阶段页显示。
- 顶部导航、岗位详情、重新分析、原岗位卡片与管理功能继续复用；新布局使用 `components/pipeline.css`。

## 验证

`node --test tests/pipeline-stages.test.mjs` 验证六阶段分组、旧数据保留、阶段内容通过原服务端校验后的往返、大小和数量限制。
