# EasyToGetGoodJob 公开应用上线准备

本轮只检查现状、记录实施路线。尚未开放多用户权限，也未把最新本地版本发布到云端。

## 已核实的现状

- 前端：React、TypeScript、Tailwind；全栈路由：Vinext / Vite。
- 后端：Cloudflare Workers；数据库：Drizzle + D1。不是上传静态网页文件就能完整运行的项目。
- `.openai/hosting.json` 已有关联的 Sites 项目。平台查询显示已有公开站点和第 17 个历史版本：<https://internship-tracker-lwj.lwj21376150.chatgpt.site>。这不证明云端包含最近的本地修改，也不证明各业务接口已适合公众使用。
- `public/manifest.webmanifest`、`public/sw.js` 已提供 PWA 基础；线上仍需验证 HTTPS、手机布局、安装与更新体验。
- 岗位、简历、面试复盘表均有 `owner_id`，主要查询已按所有者过滤；多用户完整隔离尚未通过双账号集成测试。
- 当前身份来自 Sites 注入的 `oai-authenticated-user-id`，API 进一步要求等于 `OWNER_USER_ID`。本地预览使用模拟账号，不能当作公网认证。
- PDF 在浏览器中提取文字；服务器保存提取后的简历文本。当前不保存 PDF 原文件，不需要为此单独配置文件存储服务。
- 目前简历匹配使用本地规则和关键词，没有接入大模型 API。存在个人化默认简历、分值与建议，开放给所有人前必须改为每人的真实简历依据。

## 最大的阻塞

当前产品是“个人专用工作区”。需要先完成正式身份验证与独立用户工作区，再开放注册。仅删除 `OWNER_USER_ID` 判断不够：新用户不能继承作者的默认简历，也不能把客户端伪造的身份请求头当作凭证。

## 第一版产品形态

建议先做可通过链接访问的 Web App，并保留 PWA 安装能力。支持安装的浏览器中可以添加到桌面；它不等于已上架 iOS / Android 应用商店。应用商店版本另行规划。

## 待选择的部署路线

### 路线 A：沿用 Sites，使用 ChatGPT 登录

- 能复用目前托管、身份集成与 D1 绑定，代码迁移最少。
- 首页公开，登录后进入各自工作区。
- 是否适合目标用户，取决于他们能否使用该站点及 ChatGPT 登录；应先邀请目标设备上的测试者验证。
- 平台托管数据库，不需要先购买独立云服务器；使用额度以当前账号可用配置为准。

### 路线 B：独立托管，使用邮箱注册登录

- 更适合不希望依赖 ChatGPT 账号的产品体验。
- 先确定主要用户地域与可达性，再选托管平台、身份服务和邮件服务。
- 若使用 Cloudflare Workers + D1，可以保留较多后端代码；迁移到普通 Node 云服务器需要处理 Cloudflare 专有运行时与数据库访问层，不能直接复制启动命令。
- 独立托管必须由服务器验证登录会话 / 签名令牌，替换对 Sites 身份请求头的信任。
- 需要准备托管账号、正式身份服务配置；邮箱验证或找回密码还需可用的邮件发送配置。域名可稍后绑定。

## 不依赖购买服务的实施清单

1. 保留 Git 历史和本地数据库；公网使用独立数据库，个人数据迁移单独处理。
2. 收拢分散的认证入口：`lib/owner-auth.ts` 和 jobs、resumes、import-url、reorder、analyze 等 API 内重复的身份判断。
3. 把首页头像连接到真正的登录 / 退出流程；提供新用户空状态与简历上传引导。
4. 清理 `lib/resume-profiles.ts` 的个人默认简历；调整 `lib/resume-matcher.ts` 的个人化打分与行动建议。无简历时显示待完善，不生成像真实分析一样的默认分数。
5. 验证所有查询、更新、删除、导入导出及复盘关联岗位的用户归属；客户端排序偏好等缓存需要按用户区分或在切换账号时重置。
6. 为注册、导入招聘链接、批量分析等加入必要的频率及数量限制。现有网页抓取虽有限制大小和跳转检查，但还不能替代完整的公开服务防滥用措施。
7. 在独立测试数据库用 A、B 两个账号验证：互不可见、不能使用对方 ID 修改记录、导出只含自己的资料、退出后不可读取私密接口。
8. 用实际云端来源测试招聘站抓取、PDF 读取、移动端和 PWA；本地成功不代表招聘网站一定允许云端 IP 抓取。
9. 再部署可对外邀请的版本，配置日志、错误观察、备份和回滚；公开范围沿用最终选定的产品方案。

## 需要准备什么

| 项目 | 第一版是否必须 | 说明 |
| --- | --- | --- |
| 托管运行环境 | 必须 | 复用 Sites 或选择独立托管，不一定是传统云服务器 |
| 云数据库 | 必须 | 保存每个账号的岗位、简历文字、日程与复盘 |
| 正式登录 | 必须 | Sites ChatGPT 登录，或经验证的独立邮箱登录 |
| 邮件服务 | 邮箱方案需要 | 用于验证账号、找回密码等 |
| 自有域名 | 可选 | 展示作品更完整，可在测试通过后购买和绑定 |
| 大模型 API | 可选 | 现有 PDF 提取不需要；如升级为语义匹配，需要另外选模型、预算与隐私处理方式 |
| PDF 文件存储 | 当前不需要 | 只有未来保留原 PDF、下载或预览原文件时才需要 |

密钥通过本机环境配置或托管平台的秘密变量输入，不写入 Git，也不要直接发在聊天里。
