# 保存与恢复项目版本

当前项目使用本机 Git 保存代码版本，不会自动上传到网上。

## 每次修改前保存一次

在项目根目录执行：

```powershell
npm.cmd run version:save -- "修改前：首页徽章版"
```

修改满意后再保存一次：

```powershell
npm.cmd run version:save -- "首页新版：调整标题和导航"
```

不写说明也可以，命令会使用北京时间命名。此命令保存全部未被忽略的新增、修改和删除文件。新加入的私人文件应先写入 `.gitignore`。

## 查看旧版

VS Code 左侧“源代码管理”中查看历史图，也可以执行：

```powershell
git log --oneline -15
git show 版本号:app/page.tsx
```

单文件可在 VS Code 的“时间线”里选择历史提交、对比内容。

## 找回旧版而不覆盖当前项目

先保存当前修改，再用独立文件夹查看旧版本：

```powershell
git worktree add --detach ../EasyToGetGoodJob-old 版本号
```

旧版本会出现在旁边的新文件夹中，当前项目不受影响。运行旧版本还需要单独准备依赖和本地配置；不要复制正在使用的数据库来回覆盖。

如果要把某次修改整体撤销，可以让助手根据提交号执行 `git revert`，产生一条新的撤销提交，历史仍保留。避免使用 `git reset --hard` 或直接覆盖当前文件夹。

## 保存范围与限制

- 保存源代码、样式、项目文档、图片和锁文件。
- 排除 `.env.local` 等真实配置、依赖、构建输出、工具缓存和 `.wrangler` 本地数据库；保留 `.env.example` 示例。
- 岗位、简历等个人数据请通过现有“资料导入与导出”单独导出备份。Git 不是岗位数据库备份。
- Git 记录存在本机 `.git` 文件夹中，不要删除。要防范硬盘损坏，还需另行备份整个项目或配置远程仓库；当前没有进行上传。
- 首次提交之前的历史不能通过 Git 自动补回；已有截图、原图或临时备份仍可用于找回部分内容。

以后让助手修改时，可直接说明：“先保存当前 Git 版本，修改完成后再保存一个版本。”
